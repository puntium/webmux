# Audit: settings, connection log, status/modals, wire protocol (PARITY §10–13)

Auditor: independent; nothing here was built by me. Binary audited: `gtk/ghostty/zig-out/bin/webmux-gtk` as found on 2026-11-04. It is a debug build: app.log says "This is a debug build", so the timings below are debug timings.

## How this was exercised

- **Runs** (all through `webmux-dev/headless`, all stopped, nothing left running):
  - `/tmp/wm-lbbNZq`, `/tmp/wm-fLLEY9`: dev mode (`--host`) with the app pointed at a recording man-in-the-middle proxy (`WEBMUX_GTK_DEV_SOCKET=/tmp/wm-aud4/p.sock`).
  - `/tmp/wm-MoGxEc`: the full connection flow (connection page form, real deploy of the payload, two hosts `alpha`/hostA with key auth and `beta`/hostB with a password through askpass, GNOME Keyring on the private bus, a tunnel killed and healed). The ssh stand-in was my own wrapper `/tmp/wm-aud4/fssh`. It calls `webmux-dev/fake-ssh` but puts the recording proxy in place of the `-N -L` socat relay, so every tunnel byte was recorded.
  - `/tmp/wm-h0BzFS`, `/tmp/wm-JHOjOM`, `/tmp/wm-P3Mdu7`, `/tmp/wm-IdVj6z`: restarts with hand-edited, corrupt and unusual `config.json` files (via `-- XDG_CONFIG_HOME=/tmp/wm-aud4/cfgN`).
  - `/tmp/wm-u3usL8`: the crash reproduction.
- **Proxy**: `/tmp/wm-aud4/proxy.py` is a unix-socket HTTP/WebSocket man-in-the-middle. It logs every request and response head and body, decodes WebSocket frames in both directions, and has a control socket to inject server→client frames (text or raw bytes), kill sockets, or close a socket in the middle of a frame. The recordings are in `/tmp/wm-aud4/proxy.log`, `proxy2.log` and `tun-hostA.log`/`tun-hostB.log`.
- **Input**: real keystrokes through `webmux-dev/realkeys` wherever a widget had to receive them (settings controls, theme dropdown, Ctrl+, Ctrl+Shift+G, Escape, Ctrl+F, Ctrl+Shift+C, Ctrl+V). The headless seat has no pointer, so clicks went through the panels' control commands, which call the same handlers.
- **Screenshots**: `panels-screenshot` and `grim` (`/tmp/wm-aud4/*.png`).
- **Shorthand** used in the reproduction steps: `W="webmux-dev/wmctl -s $D/ctl.sock"`, run from `gtk/ghostty`.

## Defects outside the checklist

- **D1 — The whole UI freezes while a snapshot is replayed (all windows, all hosts).**
  - Measurements (debug build): a synthetic 20 MB snapshot froze the GTK main loop for about 210 s, during which even `wmctl help` timed out. A real 51 KB scrollback snapshot took about 1 s.
  - Likely cause: `termio/Webmux.zig:246-275` (`sinkSnapshot`) holds the surface's `renderer_state.mutex` for the whole replay, and the main thread blocks on it.
  - Release builds will be much faster, but the freeze scales with snapshot size and hits every pane and host, not just the one reconnecting. With several large panes reconnecting at once (after a server restart) the stalls add up.
  - Repro: dev run through the proxy, then inject `{"type":"snapshot","data":<20 MB>,"cols":145,"rows":44,"title":"x","pid":1}` on one socket (the script is in `/tmp/wm-aud4`, see `proxy.py` `inject`), then poll `wmctl help`.
- **D2 — App abort on large floats in log data.** See G-04: `util.zig:64` `writeJsNumber`. Integral floats with 2^63 ≤ |f| < 1e21 panic.
- **D3 — The settings dialog produces about 10 GTK layout warnings every time it opens**, for example `Widget reports min height of 509 for width of 460, but overall min height of 550` and `Adwaita: GtkBox … exceeds AdwDialog height: requested 550 px, 509 px available`. They appear at 1200×800 and 1400×900 too. In a 900×520 window the panel runs off the bottom of the window with no scrolling (`settings-small.png`). The cause looks like the wrapped description labels with `max-width-chars` inside a Grid in an AdwDialog.
- **D4 — A corrupt `config.json` is silently discarded and then overwritten.** Nothing is written to the connection log or app.log (`Store.loadJson` swallows the parse error). The first settings change rewrites the file with no profiles, so the user's profile list is lost with no backup. Electron also overwrites, but it at least prints `config.json unreadable`. Repro: `printf '{"profiles":[{"name":"x","host":"y"}],"settings":{' > cfg/webmux-gtk/config.json`; start with `-- XDG_CONFIG_HOME=cfg`; `$W settings-set fade:=30` → the file now has `"profiles":[]`.
- **D5 — Log noise:** every attach and reconnect logs `warning(stream): invalid C0 character, ignoring: 0x18`, from the replay's own CAN byte (`replay.zig:34`).
- **D6 — After an `exit` frame the client drops the socket without answering the server's close frame** (the proxy saw a reset). This is harmless with the current host; a stricter server would log abnormal closures.
- **D7 — Titles from `title` frames are used raw**, control characters included (`T\x07itle\x1b]0;evil\x07` ended up in `dump.title` and the pane bar). In Electron, `textContent` shows them inertly. Not a security issue, but the pane bar may render boxes.
- **D8 — Toasts are per window, not per host page.** A status from a background host (an upload finishing, a paste result) appears over the host being viewed. Electron would show it only on that host's own page. It is not recorded as a deviation.
- **D9 — Possible wrong-host dispatch** (needs confirming by the workspace auditor).
